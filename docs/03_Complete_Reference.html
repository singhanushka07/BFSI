2. Local Setup — Step by Step

Prerequisites

  • Python 3.11+ (python --version)
  • Node.js 18+ (node --version)
  • OpenAI API key with GPT-4o access
  • Git

Backend Setup

1
Create virtual environment
cd backend python -m venv venv # Windows: venv\Scripts\activate # Mac/Linux: source venv/bin/activate
2
Install dependencies
pip install -r requirements.txt
This installs: FastAPI, uvicorn, LangGraph, LangChain, langchain-openai, ChromaDB, pypdf, SQLAlchemy, python-jose, passlib, and more.
3
Configure environment
cp .env.example .env # Edit .env: OPENAI_API_KEY=sk-your-key-here SECRET_KEY=generate-a-random-64-char-string DATABASE_URL=sqlite:///./bfsi_risk.db
4
Run the backend
uvicorn main:app --reload --port 8000
Backend starts at http://localhost:8000
Interactive API docs: http://localhost:8000/api/docs

Frontend Setup

5
Install npm packages
cd frontend npm install
Installs: React, Vite, Tailwind CSS, Framer Motion, Recharts, Zustand, Axios, React Router, Lucide icons
6
Set frontend env (optional for dev)
cp .env.example .env # VITE_API_URL=http://localhost:8000/api # (Vite proxy already handles /api → 8000 for dev)
7
Start dev server
npm run dev
Frontend at http://localhost:5173
The vite.config.js proxy routes /api/* → localhost:8000 automatically.
Both services must be running simultaneously: backend on port 8000, frontend on port 5173. They communicate through the Vite proxy during development.

6. Data Flow Walkthrough

Complete data flow for a single "Run Analysis" request (streaming path via SSE):

1
Browser → FastAPI (SSE): React sends POST /api/agents/analyze-stream?token={jwt}. Auth is via query param because the EventSource API cannot set headers. The server opens an SSE stream back to the browser.
2
JWT Validation: FastAPI validates the token from the query parameter, queries SQLite for the user, and injects it into the route handler.
3
LangGraph Invoked: run_full_analysis("TechCorp", "TCG") creates initial RiskState and calls graph.invoke(state).
4
Market Risk Node: Calls mock stock generator (or MCP tool), computes VaR/volatility, calls GPT-4o via LangChain chain, returns market_result dict. SSE event sent: agent_complete: market_risk.
5
Sentiment Node: Generates mock news feed, computes sentiment stats, calls GPT-4o for analysis text. SSE event sent: agent_complete: sentiment.
6
Financial Report Node: If collection_name provided, queries ChromaDB for top-5 relevant chunks. Combines RAG context + financial metrics in GPT-4o prompt. SSE event sent: agent_complete: financial_report.
7
Regulatory Node: Runs 8 compliance checks (random-weighted for demo), calls GPT-4o with violation summary for professional assessment text. SSE event sent: agent_complete: regulatory.
8
Aggregator Node: Computes weighted average: (market×0.3) + (sentiment×0.2) + (financial×0.3) + (compliance×0.2). Builds final_report dict.
9
Guardrails Validation: The guardrails agent validates all agent outputs using an LLM-as-judge pattern. Checks for hallucinations, score consistency, and factual grounding. Produces a trust_score (0–1). SSE event sent: guardrails_complete.
10
Devil's Advocate Challenge: The Devil's Advocate agent reviews the aggregated findings and challenges weak reasoning, unsupported claims, and optimistic assumptions. Generates counter-arguments for each agent's output. SSE event sent: debate_challenge.
11
Judge Verdict: The Judge agent evaluates both the original findings and the Devil's Advocate challenges. Resolves disagreements, produces a balanced verdict, and computes an adjusted_risk_score. SSE event sent: judge_verdict.
12
Storage: FastAPI route saves a RiskAnalysis record to SQLite with all scores, agent JSON output, debate analysis, guardrails result, adjusted risk score, and trust score.
13
SSE Complete: Final analysis_complete event sent with the full final_report JSON. The SSE stream closes. Dashboard renders the gauge, agent panels, debate panel, trust score badge, and charts.
14
Chat (Post-Analysis): User can open the ChatPanel to ask follow-up questions about the analysis. Messages are sent via POST /api/chat/message, stored in the chat_messages table, and answered by GPT-4o with the full analysis context.

7. Error Handling Strategy

Backend — Agent Failures

Each LangGraph agent node is wrapped in try/except. If GPT-4o fails (rate limit, network error), the agent falls back to metric-computed analysis text and still returns a valid score. The error is stored in state["error"] but doesn't crash the pipeline.

Backend — HTTP Errors

FastAPI raises HTTPException with specific status codes: 400 (duplicate email), 401 (invalid JWT), 404 (analysis not found), 422 (Pydantic validation failed), 500 (agent analysis failed).

Frontend — Axios Interceptor

401 Unauthorized responses automatically clear the Zustand auth store and redirect to /login. Other errors are caught in try/catch blocks and displayed via react-hot-toast error toasts.

Frontend — Loading States

All async operations show loading states: spinner on the Analyze button while agents run, Loader2 icon on PDF upload. Disabled states prevent double-submissions.

SSE Stream Error Recovery

If the SSE connection drops mid-analysis, the frontend detects the onerror event and falls back to polling /api/agents/history/{id} for the completed result. The backend writes partial progress to the database, so results are never lost. Server-side generator catches agent exceptions and sends an error SSE event before closing the stream.

Chat Error Handling

Chat endpoint errors (GPT-4o failures, rate limits) return a structured error response. The ChatPanel displays a retry button. Messages are only persisted to chat_messages after a successful AI response — failed attempts do not pollute the conversation history. Input is validated and sanitized before being passed to the LLM prompt.

Debate Timeout Handling

The Devil's Advocate and Judge agents have a configurable timeout. If either agent exceeds the timeout, the pipeline continues with the original aggregated scores (no adjustment). A debate_timeout SSE event is sent so the frontend displays a warning that the debate phase was skipped. The guardrails trust score is still computed independently.

Guardrails Fallback

If the guardrails validation (LLM-as-judge) fails, the system defaults to a trust_score of null and proceeds without blocking the analysis. The TrustScoreBadge shows an "Unverified" state. No hallucination flags are raised, and the original scores are preserved.

8. Security Model

ThreatMitigation
Password theft via DB breachbcrypt with cost factor 10. Even with the hash, brute-force is computationally infeasible at scale.
Token theft / replayJWTs expire in 30 minutes. SECRET_KEY is never exposed. HTTPS in production encrypts tokens in transit.
Cross-user data accessAll database queries filter by user_id = current_user.id. User A cannot access User B's analyses or documents.
Malicious file uploadFile extension validated (.pdf only). File saved with user ID prefix to prevent path traversal. pypdf reads text only — no code execution.
SQL injectionSQLAlchemy ORM uses parameterized queries. No raw SQL string construction anywhere in the codebase.
Cross-Origin requestsCORS whitelist restricts which origins can make API calls. Wildcard * is never used for credentials.
API key exposureOPENAI_API_KEY stored only in server-side .env. Never in frontend code, never in responses, never in logs.
Prompt injection via PDFsPDF content is retrieved by ChromaDB and included as context — not executed. GPT-4o's system prompt establishes the analyst role, making injection attempts ineffective for role hijacking.
Chat input injectionChat messages are sanitized before inclusion in the LLM prompt. User input is treated as data, not instructions. The system prompt for chat is hardcoded and cannot be overridden by user messages. Maximum message length is enforced.
SSE / streaming authSSE endpoints authenticate via JWT passed as a query parameter (?token=...) because the browser EventSource API cannot set custom headers. Tokens are validated identically to Bearer header auth. HTTPS encrypts the token in transit; query param tokens are short-lived.

9. Deployment Checklist

Pre-deployment

☐  Generate a cryptographically secure SECRET_KEY: openssl rand -hex 32
☐  Set CORS_ORIGINS to production Vercel URL only (remove localhost)
☐  Set VITE_API_URL in Vercel to the Render backend URL
☐  Verify OPENAI_API_KEY is set in Render env vars, not in code
☐  Run npm run build locally to catch any build errors before deploying
☐  Test /api/health endpoint returns 200 after Render deploy
☐  Test registration + login flow end-to-end on the live deployment
☐  Test one full risk analysis on the deployed platform

Render-specific Notes

  • Free tier services sleep after 15 minutes of inactivity → 30–60 second cold start. Expected behavior for free tier.
  • ChromaDB data is stored in ./chroma_db/ — this is ephemeral on Render free tier. Uploaded PDFs will need to be re-uploaded after each deploy.
  • SQLite bfsi_risk.db is also ephemeral — user accounts reset on redeploy. Use Render's managed PostgreSQL (free tier) for persistent user data in production.
  • Render auto-deploys from the connected GitHub branch on every push.

11. Glossary

TermDefinition in context of this project
AgentA LangGraph node that performs a specific analysis task (market/sentiment/financial/regulatory), using LangChain + GPT-4o to produce a risk score and analysis text.
RAGRetrieval-Augmented Generation. Technique where relevant document chunks are retrieved from a vector database and injected into the LLM prompt as context.
Vector EmbeddingA high-dimensional numerical representation of text that encodes semantic meaning. Generated by text-embedding-3-small. Similar meanings → similar vectors.
Cosine SimilarityMeasure of similarity between two vectors based on the angle between them. Used by ChromaDB to rank chunks by relevance to a query.
LangGraph StateA TypedDict that flows through all agent nodes in the graph. Each node reads from and writes to the same state object.
MCPModel Context Protocol. A standardized interface for AI models to request external data and tools via a declared tool manifest.
JWTJSON Web Token. A signed, self-contained token encoding user identity and expiry. Stateless — no server-side session storage needed.
VaR (Value at Risk)Statistical measure of potential loss. VaR(95%) = maximum expected daily loss with 95% confidence under normal market conditions.
BetaMeasure of a stock's volatility relative to the market. Beta > 1 = more volatile than market. Beta < 1 = less volatile.
D/E RatioDebt-to-Equity. Total debt ÷ total equity. Higher = more leveraged = higher financial risk.
ROEReturn on Equity = Net Income ÷ Total Equity. Measures how efficiently a company uses shareholders' capital.
Current RatioCurrent Assets ÷ Current Liabilities. Ratio > 1 = can cover short-term obligations. Ratio < 1 = potential liquidity risk.
Basel IIIInternational banking regulations defining minimum capital requirements for financial institutions to withstand economic stress.
AML/KYCAnti-Money Laundering / Know Your Customer. Regulatory requirements to verify customer identities and monitor transactions for suspicious activity.
GDPRGeneral Data Protection Regulation (EU). Rules governing personal data collection, storage, and processing. Violations carry massive fines.
MiFID IIMarkets in Financial Instruments Directive II (EU). Regulates investment services and financial markets for transparency and investor protection.
SOX 404Sarbanes-Oxley Act Section 404. Requires management to assess and report on the effectiveness of internal controls over financial reporting.
ChromaDB CollectionA named namespace within ChromaDB that holds a set of embeddings + documents + metadata. One collection per uploaded document in this project.
PydanticPython data validation library. Defines data shapes with Python type hints. FastAPI uses it to validate request/response bodies automatically.
SQLAlchemy ORMObject-Relational Mapper. Maps Python classes to database tables. Allows writing database queries in Python instead of SQL.
CORSCross-Origin Resource Sharing. Browser security mechanism. The backend must explicitly allow the frontend's origin to make API calls.
ZustandMinimal React state management library. Used for global auth state (user + JWT token) with localStorage persistence.
SSE (Server-Sent Events)HTTP-based protocol for unidirectional server-to-client streaming. The server pushes events over a single long-lived connection. Used to stream agent progress during analysis in real time.
Devil's Advocate AgentA debate agent that challenges the findings of the four analysis agents. It identifies weak reasoning, unsupported claims, and overly optimistic assessments, generating counter-arguments to stress-test the analysis.
Judge AgentA debate-resolution agent that evaluates both the original analysis findings and the Devil's Advocate challenges. Produces a balanced verdict and computes an adjusted risk score reflecting the debate outcome.
GuardrailsA validation layer that checks agent outputs for quality, consistency, and factual grounding before they reach the user. Uses an LLM-as-judge pattern to detect hallucinations and scoring anomalies.
Trust ScoreA confidence metric (0–1) produced by the guardrails agent. Reflects how well agent outputs pass hallucination checks, internal consistency validation, and factual grounding tests. Displayed as a badge in the UI.
Hallucination DetectionThe process of identifying when an LLM generates claims not grounded in the provided data or context. The guardrails agent uses a second LLM call (LLM-as-judge) to verify that agent outputs are consistent with their input data.
Chat MemoryPersistent storage of conversational context in the chat_messages table. Enables multi-turn follow-up conversations about completed analyses, with the AI retaining awareness of prior questions and answers in the session.
