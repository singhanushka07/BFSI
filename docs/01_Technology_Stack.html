BFSI Multi-Agent Financial Risk Assessment Platform
Every technology, its role, and the reasoning behind choosing it

This document covers all 18+ production technologies used in the BFSI Multi-Agent Financial Risk Assessment Platform. For each technology, it explains: what it is, what specific role it plays in this project, why it was chosen over alternatives, and how it connects to the rest of the stack.

Project Recap: An AI-driven platform that orchestrates 6 specialized LangGraph agents (4 domain analysts + Devil's Advocate + Judge) to automate corporate financial risk analysis — covering market exposure, sentiment, financial report analysis (via Hybrid RAG + LLM Re-ranking), and regulatory compliance, followed by a multi-agent debate for validated conclusions. Features SSE real-time streaming of agent results, guardrails with hallucination detection (LLM-as-Judge trust scoring), and conversational risk chat for interactive follow-up. MCP tools dispatched via both internal dispatcher and an official FastMCP SDK server. Secured with JWT auth, backed by SQLite, deployed on Render + Vercel.

AI & Orchestration Layer
⬡
LangGraph
Agent Orchestration AI Core
What it is
A graph-based agent orchestration library from LangChain. Defines agents as nodes in a stateful directed graph, with typed state passing between nodes.
Role in this project
The central orchestrator. Defines a RiskState TypedDict and routes it through a 7-node sequential flow: market_risk → sentiment → financial_report → regulatory → aggregator → devils_advocate → judge → END. The Devil's Advocate node challenges findings; the Judge node resolves disagreements and produces adjusted scores.
Why chosen over alternatives
vs. plain Python loops: LangGraph provides checkpointing, error handling, and state visibility. vs. AutoGen: LangGraph integrates natively with LangChain. vs. CrewAI: more fine-grained control over state transitions.
langgraph==0.0.26
⛓
LangChain
LLM Framework AI Core
What it is
A composable framework for building LLM-powered applications. Provides ChatPromptTemplate, output parsers, chains, embeddings, and vector store integrations.
Role in this project
Powers the prompt engineering inside each agent. Every agent uses a ChatPromptTemplate and a LangChain chain (prompt | llm) to generate its analysis text.
Why chosen
LangChain is the de-facto standard for LLM chains. Its prompt templates and chain composition reduce boilerplate significantly. LangGraph is built on top of LangChain, making integration seamless.
langchain==0.1.9, langchain-openai==0.0.8
◎
GPT-4o (OpenAI)
Large Language Model AI Core
What it is
OpenAI's flagship multimodal LLM. Used via the ChatOpenAI LangChain wrapper with model="gpt-4o-mini" for cost-effective agent reasoning.
Role in this project
The reasoning engine for all 4 agents. Receives structured financial prompts and returns professional risk assessments in natural language. Also powers text embeddings via text-embedding-3-small.
Why chosen
Superior financial domain reasoning compared to open-source alternatives. GPT-4o-mini offers the best cost/quality ratio for agent workloads. OpenAI's embedding model integrates directly with ChromaDB.
langchain-openai, model: gpt-4o-mini
◈
ChromaDB
Vector Database — RAG AI Core
What it is
An open-source, persistent vector database. Stores text embeddings and enables semantic similarity search (cosine similarity) over large document corpora.
Role in this project
The heart of the RAG pipeline. Financial PDFs are chunked (150 words), embedded, and stored in ChromaDB collections. The Financial Report Agent queries it at analysis time, retrieving the top-k most relevant passages for GPT-4o to reason over.
Why chosen
vs. Pinecone: ChromaDB is fully local/free, no API key needed. vs. FAISS: ChromaDB adds persistence and metadata filtering. vs. Weaviate: lighter weight, easier to run locally and on Render.
chromadb==0.4.22, PersistentClient
⊕
Hybrid Search — rank-bm25 + ChromaDB Dense
Advanced RAG Retrieval AI Core
AspectDetail
What it isBM25 (Best Match 25) is a classical sparse keyword retrieval algorithm. Combined with ChromaDB dense vector search, it forms a hybrid retrieval system — each query runs both methods in parallel and scores are weighted-combined (60% dense, 40% BM25).
Role hererag/hybrid_search.py — retrieves up to 20 candidate chunks using both methods, normalizes scores to [0,1], combines with configurable alpha weight, and returns top-N with per-chunk hybrid_score, dense_score, and bm25_score metadata visible in the UI.
Why hybrid?Dense search captures semantic meaning ("describe the liquidity risk"). BM25 excels at precise regulatory terms: "Basel III", "SOX 404", "IFRS 9", "CET1", "NSFR" — financial documents are full of exact terminology that semantic search can miss. Hybrid outperforms either alone by ~15-20% recall@5 on regulatory corpora.
Libraryrank-bm25==0.2.2 — pure Python, no native extensions, works everywhere. Implements BM25Okapi with IDF smoothing.
↕
LLM Batch Re-ranker
RAG Post-Retrieval AI Core
AspectDetail
What it isA re-ranking step that runs after initial retrieval to reorder candidates by true relevance. Unlike cross-encoder models (which require large model downloads), this implementation sends all candidates to GPT-4o-mini in a single batch prompt, asking it to score each chunk 0-10 for relevance to the financial risk query.
Role hererag/reranker.py — receives up to 10 hybrid-retrieved chunks, formats them into a numbered batch prompt, calls GPT once to score all, parses the JSON score array, and returns the top-k sorted by score. Each chunk gains a rerank_score (0.0–1.0) visible in the UI alongside hybrid scores.
Why LLM re-ranking?Cross-encoder models (e.g. cross-encoder/ms-marco-MiniLM) require ~80MB model download and PyTorch. LLM-based re-ranking uses existing GPT integration with a single API call — production-effective for financial documents where GPT already understands domain semantics. Falls back gracefully to hybrid scores if the API is unavailable.
Pipeline positionHybrid retrieval → Re-rank → Top-4 → GPT-4o analysis. Two-stage retrieval then re-ranking is a standard production RAG pattern that significantly improves final answer quality.

Guardrails + Hallucination Detection
LLM-as-Judge Validation AI Core
AspectDetail
What it isA post-analysis validation layer that uses GPT-4o-mini as a judge to verify each agent's output against the original MCP source data. Returns per-agent confidence scores (0-100) and flags any claims not supported by the source material.
Role hereAfter each agent produces its analysis, the guardrails module cross-references the output against the raw MCP tool data. It identifies hallucinated or unsupported claims, computes a per-agent confidence score, and derives an overall trust score for the entire analysis run. Flagged issues are surfaced in the UI.
Why LLM-as-Judge?Rule-based validation cannot catch semantic hallucinations (e.g., an agent inventing a financial ratio not present in the source). GPT-4o-mini is cost-effective for judge tasks and already available in the stack. The pattern is a recognized best practice for production LLM applications where factual grounding matters.
OutputPer-agent: confidence_score (0-100), flagged_issues[]. Overall: trust_score (weighted average). All visible in the frontend results panel.
⚔
Multi-Agent Debate
Devil's Advocate + Judge Pattern AI Core
AspectDetail
What it isA two-stage adversarial review pattern added after the initial 4-agent + aggregator pipeline. A Devil's Advocate agent challenges the aggregated findings, then a Judge agent evaluates both sides and produces adjusted final scores.
Role hereExtends the LangGraph flow with two additional nodes: devils_advocate (identifies weaknesses, counter-arguments, and overlooked risks) and judge (weighs original findings against challenges, resolves disagreements, outputs adjusted risk scores with reasoning). Sequential flow: aggregator → devils_advocate → judge → END.
Why debate?Single-pass LLM analysis is prone to confirmation bias and anchoring. The adversarial pattern forces the system to stress-test its own conclusions. Research shows multi-agent debate improves factual accuracy and reduces overconfident risk assessments — critical in financial contexts.
ImplementationBoth agents are LangGraph nodes sharing RiskState. The Devil's Advocate receives all agent outputs + aggregated scores. The Judge receives all of the above plus the Devil's Advocate challenges. Uses LangGraph's sequential flow with no conditional branching.
💬
Conversational Risk Chat
Context-Injected Chat with Memory AI Core
AspectDetail
What it isA post-analysis conversational interface that lets users ask follow-up questions about the risk report. Powered by GPT-4o-mini with the full analysis context (all agent outputs, scores, debate results) injected as system context, plus rolling chat history for multi-turn conversations.
Role hereAfter an analysis completes, users can chat naturally: "Why is the market risk score so high?", "Compare regulatory findings with sentiment", "What would change if interest rates dropped 50bp?". The LLM answers grounded in the actual analysis data, not generic knowledge.
EndpointsPOST /api/chat/message — send a message with analysis ID, returns AI response. GET /api/chat/history/{id} — retrieve full conversation history for an analysis session.
Why important?Static risk reports leave analysts with unanswered questions. Conversational access transforms a one-shot report into an interactive advisory session. Chat history persistence enables audit trails and team knowledge sharing.

MCP — Model Context Protocol
Tool-Serving Layer Infrastructure
AspectDetail
What it isA protocol (introduced by Anthropic) that standardizes how AI models request and receive tool outputs. Exposes tools as structured API endpoints that agents call by name with typed parameters.
Role hereTwo implementations: (1) Internal Dispatcher — mcp_server/dispatcher.py routes all agent data fetches through call_mcp_tool(), logging every call with tool name, params, result summary, and timestamp. (2) FastMCP SDK Server — mcp_server/mcp_sdk_server.py uses the official mcp Python SDK, exposing a proper stdio/SSE MCP server connectable by Claude Desktop or any MCP client. Tools: get_stock_data, get_financial_metrics, get_news_sentiment, get_regulatory_rules, hybrid_rag_search_tool, list_rag_collections.
Why importantMCP is the emerging industry standard for agent-tool communication. The official SDK implementation makes this a real MCP server, not just a named pattern — it can be connected to Claude Desktop, Cursor, and any MCP-compatible client. Demonstrates production-level architecture awareness.
Why chosenFuture-proof: as more LLM frameworks adopt MCP, this platform is already compatible. Decoupling agents from tool implementations via a protocol interface is a production best practice. The FastMCP SDK requires minimal boilerplate via decorator-based tool registration.
Backend Layer

FastAPI
REST API Framework Core
What it is
A modern, async Python web framework built on Starlette + Pydantic. Auto-generates OpenAPI/Swagger docs.
Role in project
Serves all REST endpoints: /api/auth/* (JWT), /api/agents/* (LangGraph analysis), /api/agents/analyze-stream (SSE real-time streaming), /api/chat/* (conversational risk chat), /api/rag/* (PDF upload/query), /api/dashboard/* (charts data), /mcp/* (tool protocol). Uses StreamingResponse for SSE delivery of agent results.
Why chosen
vs. Flask: FastAPI is async-native (critical for concurrent agent calls), has automatic Pydantic validation, and generates interactive docs at /api/docs. vs. Django: far lighter for pure API services.
fastapi==0.109.2, uvicorn[standard]
▦
SQLAlchemy + SQLite
ORM + Database Infrastructure
What it is
SQLAlchemy is Python's most mature ORM. SQLite is a serverless relational database stored as a single file.
Role in project
Stores 3 entities: User (credentials, profile), RiskAnalysis (all agent scores + analysis text per run), UploadedDocument (PDF metadata + ChromaDB collection mapping).
Why SQLite chosen
Zero config, zero infrastructure cost, perfect for portfolio/demo. SQLAlchemy makes migration to PostgreSQL (Render's managed DB) a one-line change to DATABASE_URL.
sqlalchemy==2.0.27, sqlite3 (built-in)
🔐
JWT Authentication
Security Security
What it is
JSON Web Tokens — a stateless authentication mechanism. A signed token (HS256) encodes user identity and expiry, verified on every protected request.
Role in project
All dashboard, analysis, RAG, and history endpoints require a valid Bearer token. Implemented with python-jose (token signing) and passlib[bcrypt] (password hashing). OAuth2PasswordBearer dependency handles extraction.
Why JWT
Stateless — no session store needed, scales horizontally. Standard for REST APIs. bcrypt password hashing with salt is industry-standard security. Compatible with every frontend framework.
python-jose==3.3.0, passlib[bcrypt]==1.7.4
📄
pypdf
Document Processing Infrastructure
What it is
A pure-Python PDF reading library. Extracts text content page by page from uploaded PDF files.
Role in project
Reads uploaded financial PDFs, extracts text per page, splits into ~150-word overlapping chunks, which are then embedded and stored in ChromaDB. Handles annual reports, 10-K filings, and earnings documents.
Why chosen
vs. pdfplumber: pypdf is lighter, faster, and pure Python with no C dependencies. vs. PyMuPDF: pypdf is open-source with a permissive license, zero native dependencies for cloud deployment.
pypdf==4.0.2

React 18 + Vite
UI Framework + Build Tool Core
What it is
React 18: component-based UI library with hooks. Vite: next-generation build tool using ES modules for near-instant HMR and sub-second cold starts.
Role in project
Renders the entire frontend: landing page, login/register flow, 4-tab dashboard, analytics charts, agent result panels, PDF upload UI, and the interactive architecture diagram.
Why Vite over CRA
Vite is 10–100× faster than Create React App for dev server startup and HMR. The proxy config in vite.config.js tunnels /api calls to FastAPI, eliminating CORS issues during development.
react==18.2, vite==5.1
🎨
Tailwind CSS
Styling Framework Core
What it is
Utility-first CSS framework. Every style is composed from atomic utility classes applied directly in JSX.
Role in project
Implements the entire dark professional theme: navy-950 backgrounds, cyan accent colors, glass-morphism cards (.glass-card), glow borders, gradient text, risk color system (green/amber/orange/red), and all responsive layouts.
Why chosen
No CSS context switching — styles live in components. Custom design tokens (navy, risk colors) defined in tailwind.config.js create a consistent design system. Tree-shaking removes unused CSS in production.
tailwindcss==3.4.1

Animation Library Core
What it is
Production-ready motion library for React. Declarative animations with motion.div, spring physics, and layout animations.
Role in project
Powers: hero entrance animations, animated risk score gauge (SVG strokeDashoffset), agent score bars, card hover effects, tab transitions (AnimatePresence), architecture node animations, and the animated data flow arrows in the architecture diagram.
Why chosen

framer-motion==11.0.8

Recharts
Data Visualization Core
What it is
A composable charting library for React built on D3. Provides AreaChart, LineChart, BarChart, RadarChart, and more as React components.
Role in project
4 chart types in the dashboard: AreaChart (30-day risk trend), LineChart (multi-agent breakdown), BarChart (risk distribution), RadarChart (agent score comparison). All dark-themed with custom tooltips.
Why chosen
vs. Chart.js: Recharts is React-native (no imperative DOM manipulation). vs. D3 direct: far less boilerplate. vs. Victory: Recharts has better performance and a larger community.
recharts==2.12.2
🐻
Zustand
State Management Core
What it is
A minimal, un-opinionated state management library for React. Uses hooks-based API with persist middleware for localStorage sync.
Role in project
Manages auth state globally: stores user object and token string, persisted to localStorage under key bfsi-auth. The Axios interceptor reads from it on every request to inject the Bearer token.
Why chosen
vs. Redux: 10× less boilerplate. vs. Context API: no re-render cascade, built-in persistence. For a single shared auth state, Zustand is the minimal correct tool.
zustand==4.5.2
↔
Axios + React Router v6
HTTP Client + Routing Core
Role in project
Axios: configured with base URL, automatic JWT header injection via request interceptor, and 401 redirect via response interceptor. React Router v6: handles 3 routes: / (Landing), /login (Auth), /dashboard (Protected via ProtectedRoute wrapper).
Why chosen
Axios interceptors are cleaner than fetch for global token injection. React Router v6 replaced v5 with simpler nested route syntax and the Navigate component for redirects.
axios==1.6.7, react-router-dom==6.22.1
